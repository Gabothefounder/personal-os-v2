# Opportunity engine

Routing concept only. Not software.

DEEP LIBRARY ≠ ACTIVE CONTEXT

Do not load `wisdom/` in full. Select **3–5 lenses** for the problem. If a lens file is empty, say so — do not invent the thinker.

Source notes (`people/`, `books/`) stay out of the decision unless a lens was derived from them.

Always consider `UNKNOWN_DEPENDENCIES.md` when the move would remove, automate, or “simplify” something.

If Gabriel has recorded principles or outcomes, include `GABRIEL.md`. If it is empty, do not simulate it.

These are starting sets, not mandatory casts. Swap lenses when the question is different. Prefer fewer.

- Taleb, Munger/Buffett, Greenblatt, Ferguson, Talleyrand, Aristotle/Stoic — **not in the library yet**. Do not fabricate those lenses. Name the gap and proceed with what exists.
- Ferguson’s *The Square and the Tower* lives at `wisdom/books/THE_SQUARE_AND_THE_TOWER.md` (unpopulated).

## Opportunity flow

1. Capture in `opportunities/INBOX.md`
2. If it deserves work, move a pointer to `opportunities/ACTIVE.md` (max: treat like projects — few at a time)
3. Write one analysis in `opportunities/analyses/`
4. Decision: WATCH / TEST / BUILD / KILL
5. When the outcome is known: record it in the analysis, archive if done, and update `wisdom/lenses/GABRIEL.md` only from that outcome or an explicit preference

Incubator ideas that are not opportunities stay in `incubator/IDEAS.md`.

---

## Analysis template

Every opportunity analysis should contain:

- question
- facts
- assumptions
- frontier signal / why now
- relevant lenses selected
- analysis by lens
- disagreements between lenses
- unknown dependencies
- strongest counterargument
- falsifiers
- smallest real-world experiment
- potential upside
- ruin/downside risk
- decision: WATCH / TEST / BUILD / KILL
- date for reassessment
- outcome once known

Preserve disagreements. Do not average thinkers into a fake consensus.
